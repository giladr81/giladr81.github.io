Case studyGaia GPS and onX Offroad, from public app-store reviews

Gaia's critics are long-time users, and its failures show up on the App Store.

Paywall complaints are as common on Google Play as on the App Store, but failures are as common on the App Store. onX's critics are mostly new users. I off-road in BC and have used Gaia GPS several times. I'm weighing a switch to onX Offroad because I like its trail recommendations, and I haven't found anything like them in Gaia. So I read what other users wrote when they faced the same choice, and worked out what Outside's own data would need to show before committing a team.

The two-minute version

The bet
Gaia's long-time users have two complaints: features that moved behind the paywall, like saving routes, and an app that fails with no signal or in the vehicle. Paywall complaints are common on both stores, and failures concentrate on the App Store. Reviews can't say which one ends a subscription. My bet is that they hit different people: the paywall pushes away long-time free users, and failures push away subscribers at renewal. The store split fits that bet but doesn't prove it. There's a third reason, and it's mine: trail discovery. onX recommends trails, and reviews barely capture that reason. All three can be tested before committing a team: the first two in weeks, discovery after a small build.

First move
Make the in-vehicle map a release gate now, since it's cheap. Then run two tests before committing a team: do cancellations rise after a failure, and does a limited free route-saving allowance bring long-time users back without cutting paid conversion?
How to test it on Outside's data
Compare cancellations among second-year subscribers in the 60 days after a crash, failed offline launch or sync error with similar subscribers who had none. Separately, offer a random group of lapsed long-time free users a small free route-saving allowance and measure reactivation and paid conversion against a holdout.
What would kill it
If failures don't move cancellations, reliability isn't driving churn. If the allowance doesn't bring users back, or cuts paid conversion, packaging isn't the lever. If showing popular trails doesn't move retention, discovery isn't either. If none of the three moves, the problem is the price level, and pricing goes first.

Who leaves, and which job fails

The complaints map to four jobs: keeping the routes I've built (planning and saving), navigating from the vehicle (CarPlay and Android Auto), finding the way with no signal (offline maps and login), and keeping a record (tracks and sync). The BC groups add a fact that changes the risk: members run two to four apps plus paper maps. So the threat isn't a dramatic switch. Gaia gets demoted to the backup app, and backups don't get renewed. That's a hypothesis to check against Outside's activity data.

Why onX Offroad. It's the app Gaia's critics name most as where they're going ( reviews), and the one I'm weighing. It isn't Gaia's whole market, and I can't size the off-road part from reviews: only Gaia reviews mention off-roading. The few unhappy ones say what the rest of this page says: crashes, price, and moving to onX. For hikers and hunters the comparison would be CalTopo or onX Backcountry, which I haven't run.

      Proposal

      Make offline trust a promise you can measure

      An off-road navigation app makes one promise: the map works with no signal. Track it like uptime, and hold any release that breaks it. I don't know Gaia's current numbers, so each target says how I'd set it.

      This is the reliability part of the bet. Packaging and discovery are tests, not builds (see the order of work and the test plan). The cancellation test below links this metric to renewal: the cancellation gap after a failed offline launch sets how much each point of failure is worth.

      Opens with no signal

      What it measures
      Launches with no network that show a usable map and saved items without a login prompt.
      How to set the target
      Four weeks of offline launches by app version. Target the best recent version's rate.
      Starting guess
      Hypothesis99.9% or better, with a usable map within 5 seconds.

      Crash-free trips

      What it measures
      Crash-free sessions that start with no network or on CarPlay or Android Auto, tracked apart from use in town.
      How to set the target
      Close the gap to the in-town rate. Hold any release that blanks the CarPlay map in testing.

      Nothing lost in sync

      What it measures
      Tracks, waypoints and routes that reach the account intact within 24 hours of signal returning.
      How to set the target
      Zero lost items. Until then, unsynced items say "not synced yet".

      One rule for Gaia and Trailforks

      Gaia GPS and Trailforks sign in with the same Outside account (Trailforks help), so the lockout fix belongs in that shared account system. Let the phone remember the user's login and subscription for a set period, such as 30 days, without checking online. Maps already on the phone always open. The online check happens only when someone downloads something new, which is exactly where subscription revenue needs protecting.

      How it could work
      • A signed pass on the phone. At each online check the server issues a signed token (account, plan, what it unlocks, expiry). The app keeps it in secure storage and checks the signature locally, with no network.
      • At expiry. Maps, routes and tracks already on the phone still open, and navigation and recording keep working. Only new paid downloads and premium layers wait for a check, shown as "connect to renew offline access", not a login wall.
      • Abuse, and how to bound it. A lapsed subscriber keeps at most one token period on maps already downloaded, since the server stops renewing. Each token is bound to a device, with a cap on active devices per account. Setting the clock back doesn't help: the app counts from the last server time it saw using the phone's uptime counter, which users can't change.
      • Measuring offline. Each offline launch logs a small event on the phone (app version, time to a usable map, login prompt or not, token age). Events upload at the next sync with their original timestamps, so the "opens with no signal" rate arrives a few days late but complete.

      Guardrail: premium downloads and paid conversions from accounts past their offline period. If use by lapsed accounts grows, shorten the period.

      Tell the user before they lose signal

      The measures tell the team whether the promise holds. This screen tells the user, while they can still fix it: a map gap, a login about to expire, unsaved waypoints, a missing CarPlay map.

      How I'd test it. Show it to a random half of users who download maps for a route. Measure failed no-signal launches per trip, with time to start navigating as the guardrail.

      Strategy

      Compete where Outside's portfolio helps, not on onX's trail count

      • Discovery is the third hypothesis. onX advertises miles of off-road trails and says trail reports are on every trail in its map (onX's product page). Trail recommendations are why I'm looking at onX myself, and reviews barely measure that reason. Outside already owns the discovery mechanics in Trailforks: trails, color coded by popularity, and routes other users created (Trailforks' App Store listing). But Trailforks is built for mountain biking and hiking, not off-road. So the cheap test is the mechanics, not the content. Building onX-scale off-road trail data is a content business, worth it only if that test moves retention.
      • Use what Outside already owns. Gaia GPS Premium with Outside+ costs a year on the US App Store, against US$ for Premium alone, and adds . A renewal can be an Outside+ renewal, so a fix in the shared account protects more than Gaia.
      • Road freshness is the opening. The BC groups keep raising new roads missing from maps and praising apps that show current road conditions. Backroad Status road reports are already built into Trailforks, while Gaia users load them as custom map data. Making them a built-in Gaia layer is the next layer to add, once reliability holds.

      Order of work

      What I'd do first, and what I wouldn't do

      Ranked by how many long-time critics each problem reaches (from reviews) and how badly it breaks a trip (my judgment: a lockout ends the trip, a crash costs minutes, a paywalled feature costs goodwill).

      1. Make the in-vehicle map a release gate

        The blank CarPlay map reported from , after Gaia , shows how a regression reaches users, and no release note since mentions CarPlay. Test CarPlay and Android Auto before every release and track crash-free trips apart from in-town use, so the next regression shows up within one release.

        Reaches long-time critics.

        How we'd know it worked: CarPlay map failures at zero within two releases, and the field crash-free rate matching in-town use.

      2. Test a limited free route-saving allowance

        Long-time users built routes for years, then found saving them paywalled. Offer a random group of lapsed long-time free users a small free allowance, such as a few saved routes, against a holdout.

        Reaches long-time critics.

        How we'd know it worked: reactivation goes up with no drop in paid conversion. If conversion drops, the paywall stays and the upgrade message changes instead.

      3. Turn the offline-login fix into one rule across Outside apps

        Android fixed account re-authentication, and iOS loads downloaded maps more reliably when signal is weak. What's missing is the rule behind it, built once into the shared account, and a metric that proves it holds. It reaches fewer critics, but it does the most harm.

        Reaches long-time critics.

        How we'd know it worked: staged rollout with a holdout. Offline login prompts go to zero with no drop in renewals.

      4. Make sure nothing is lost in sync

        per 100 Gaia reviews, none for onX. Show "not synced yet" first, then drive lost items to zero.

        Reaches long-time critics.

      5. Ask for a rating after a trip that worked offline

        Gaia's written App Store reviews are mostly 1 and 2-star (), yet its overall rating is from ratings. onX's Google Play reviews jumped in a month that looks like an in-app prompt. Asking right after a successful offline trip is cheap and puts satisfied users on the record. No reach line on this one, because it's a cheap add-on.

      What I wouldn't do yet

      • Cut the price across the board. The route-saving allowance tests whether the paywall change is the issue, and a lower price gives up revenue from subscribers who aren't complaining.
      • Add new map layers, even Backroad Status, before reliability holds. New content on an unreliable app makes each failure cost more.
      • Remove the account requirement. Sync and subscriptions need accounts. What hurts is checking it with no signal.

      Business case

      What reliability is worth

      Gaia GPS Premium is US$ a year (US App Store, checked ). A team of engineers for months at US$ each, fully loaded (all assumed), costs about US$. At 150,000 paying subscribers (assumed), that pays back in one year only if annual churn falls points, or points if every renewal counted at the Outside+ price. Below that, the case rests on several years of kept subscribers and on Trailforks, which the account fix also covers. The offline-login rule alone is likely a smaller job than this, since Gaia has already shipped part of it.

      Before committing a team

      How I'd test the bet with Outside's own data

      Reviews show where to look, not whether to commit a team. Cheapest checks first, and each has a result that changes the plan. Split every test by platform: reviews suggest failures matter more to App Store users, and only Outside's data can confirm it.

      Gaia's own recent releases point the same way. iOS () says downloaded maps load more reliably when cell service is spotty, and Android () fixed account re-authentication. The team has started on offline and login, which fits the bet. So the first checks should run on these versions, or they'll measure problems that may already be fixed.

      Why a B2B product manager for a consumer app

      The fix at the centre of this case is an access problem, and I've owned one: at Cisco I defined the Investigate API access model in the Umbrella console, including UX integration, user permissions and API token usage. The consumer side I'd learn from Outside's subscription data and from users like me. I haven't interviewed users for this case. The first row of the test plan is where I'd start.

      Limits of this evidence, and how to close each one

      • Reviewers skew unhappy, so reviews compare problems, not overall satisfaction. Close it with the cancellation analysis above.
      • The head-to-head uses App Store reviews, and Gaia has only in the period. Counted per 100 reviews, the failure gap looks like (range to ), but that count is inflated by how many happy users each app prompts to review, so the case uses shares of unhappy reviews. On Google Play the failure gap is small. Close it by repeating the comparison each quarter on both stores.
      • Types come from phrase matching. In hand checks, of sampled reviews per type were correctly placed, and of for long-time users. Close it with Outside's support-ticket categories.
      • onX Offroad is a vehicle app. Only Gaia reviews mention off-roading, so for Gaia's hikers and hunters the comparison is untested. Close it by splitting the telemetry by activity, and repeating this against CalTopo or onX Backcountry.
